# Rust Minimap parity inventory

This inventory describes implemented behavior and its evidence. In-game visual acceptance and an equivalent-workload C++/Rust end-to-end performance comparison remain required. The DLL is a working implementation, but these outstanding checks are not represented as completed acceptance.

C++ behavior references describe `master` at `afab7e1`; its old project is absent from this branch. The Rust workspace is now at the repository root. Historical measurements remain identified by their original revision and scope; see [source layout](../../docs/source-layout.md). The official MapForGoblins ABI declaration is retained as [a C reference header](../../docs/api/mfg_map_api.h), not compiled into Minimap.

## Explicit differences and limits

- Rust plugin ABI is independent from the former ImGui plugin ABI; Boss/Achievements are outside this migration. Controlled offline hosts support full unload/reload. Once native hooks can be enabled, core code is pinned until process exit: stop retires runtime resources and returns `STOPPED_RESIDENT = 1`, but does not unmap the core DLL. Starting a new native session requires restarting the process; no live hot-reload guarantee is made.
- Actionable metadata/atlas errors remain centered to stay readable inside circular clipping. With no drawable map, errors use full group opacity even if the preset is transparent; the border remains independent. When a partial map and an error coexist, both share the preset's group opacity. The C++ status was drawn after map composition at the top-left with independent opacity; restoring that exact partial-content text composition would require another render group. Normal loading and individual tile failures produce no overlay text.
- Shortcut edges are sampled by the update worker (target 60 Hz); render does not query keys or consume OS input. Existing bindings and hiding rules are preserved, while short-press capture and input latency require game acceptance against the former render-thread sampling.
- egui owns text shaping and antialiasing. Native bitmap artwork, transforms and stacking are preserved; pixel-identical ImGui text is not promised.
- Native filled curves are flattened once into twelve quadratic segments, then triangulated including concave contours. Quadratic strokes use connected adaptive polylines with a 0.25-pixel geometric error bound and egui antialiasing. Excessively complex, filtered, malformed or unsupported GFX recipes fail resource loading rather than substituting invented icons.
- The default terrain level remains L0, matching the existing C++ rendering path. L1/L2 directory names can be parsed; automatic coarse-level selection is not enabled.
- A missing game asset/parameter/provider is retried or omitted safely according to its source. This is not evidence that every archived game version or third-party asset package has passed visual acceptance.

## Resource and hot-path bounds

- Render does no file I/O, decompression, signature scan, INI parsing, PARAM scan, update-thread wait or GPU wait. Its snapshot/renderer locks use `try_lock`.
- Update culls the immutable marker catalog to the visible region before publishing it. Game context changes invalidate conversion caches and active tiles.
- Failed full marker builds have a separate 200 ms attempt deadline even before any valid snapshot exists; they retry after that bounded interval. Source read failures never publish a fabricated valid catalog. First resource loading remains independent of marker publication. Font upload failures retry after 250 ms; pending/ready fonts do not resubmit every waiting frame.
- File/texture admission returning zero defers work without reporting a completed-request failure. Tile DDS ranges are validated once and retained without copying/reparsing the TPF on admission retries; stale CPU-only tile jobs release their eight-job allowance. A shared ABI input limit of 32 MiB prevents oversized DDS from waiting forever. Native/provider pending textures poll once per update; provider queue pressure retries after 250 ms and accepted upload failures after one second.
- At most eight tile jobs are active. Existing jobs are still polled at capacity; stale requests are cancelled. Native atlases, tiles and Goblins share one preparation allowance of at most four uploads / about 4 MiB per update. One oversized image is allowed only into an empty batch to avoid starvation; core applies an independent global upload budget. A production callback-counter test covers count, bytes and both oversized cases across native/provider paths.
- Tile residency targets 512 entries / 64 MiB. As in the C++ implementation, the currently visible working set is protected, so tiny zoom values and deferred GPU retirement may temporarily exceed the target. Idle tiles/atlases retire after about ten seconds.
- Retained native/colored atlas DDS has a 128 MiB CPU cap. A single recolored sprite is limited to four million pixels; block-cropped decode does not expand the entire source atlas. Optional Goblins decoded artwork has a separate 64 MiB catalog cap; only visible icons queue GPU preparation, and idle GPU icons retire after ten seconds. Core texture queues and GPU residency have their own documented limits.
- Mesh batches reuse `Arc<epaint::Mesh>` vertex/index capacities while preserving native texture/layer order. Already triangulated egui meshes submit directly; text/stroke runs pass through egui's tessellator in their original order. Before painting, the ABI's frame vertex/index/mesh limits bound work; excess trailing geometry is omitted with a diagnostic. Exact limits and direct/generic triangle equivalence have regression tests.
- egui still allocates for its frame/tessellation output; measured allocations are recorded in [PERFORMANCE.md](PERFORMANCE.md), not described as zero.
