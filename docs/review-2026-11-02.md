# 累计审查与修复

审查起点为 `86cd403`，行为对照为原 C++ `afab7e1`。用户已在游戏 1.17.2、启动时 Mod loader 注入的环境确认此前功能及加载提示修复正常。本轮继续在原项目会话和注册工作树实施，没有操作游戏目录或正在运行的游戏。

本页记录提升 workspace 前的累计审查。当前分支使用仓库根目录布局，C++ 来源为独立 `master` 基线 `afab7e1`；旧 Rust commit 编号是历史证据标识，不要求存在于新的根提交历史。命令按当前布局列出，基线导出方法见 [源码布局](source-layout.md)。

## 已修正的确定问题

| 调用链与触发条件 | 修复 | 生产路径证据 |
|---|---|---|
| `GameFiles::request/release`：保留同一 TPF 的一个 token，反复请求并释放不同成员。Item/token 数有界，但已释放成员仍累积并参与原生完成时的复制 | 仅在 QUEUED、尚无原生读者时移除无消费者成员，修正剩余 token 索引及最大复制额度；PENDING 后不修改回调数据 | 1,000 次循环后仅一个成员／token；真实 native fixture 提交及完成只复制活跃的 4 字节，退休后额度归零 |
| `FileSlot::update`：核心服务锁忙或容量满返回 0，被误报为文件读取失败 | 0 表示尚未接收，250 ms 后重试；实际已接收 token 的失败仍记录并提示 | 生产资源更新覆盖拒绝、稳定等待、接收、pending 和真正 FILE_FAILED，原 token 的忙轮询语义不变 |
| `Resources::update`：八块瓦片均已读入、上传尚未接收；离屏清理只看文件 token 和 GPU pending，遗漏 CPU 源数据 | 按同一个 `Tile::active` 定义清理过期任务，连同 DDS 范围释放，恢复八任务额度；不等待十秒缓存淘汰 | 两项资源回归先在旧代码失败；移动到新区域后，旧 CPU 任务失活，新瓦片发起请求 |
| tile 每次 250 ms 重试重新解析整个 TPF／DDS；超过核心单图上限的有效 DDS 会一直被拒绝 | 缓存已验证的成员范围，重试借用原缓冲，不复制／重解析；ABI 与核心共用原有 32 MiB 输入上限，资源端提前报告超限 | 保持原缓冲地址，重试只提交 DDS 成员；合法但超限的 8192² BC1 在队列前失败，atlas 有提示、tile 只日志，均限频 |
| atlas、tile、Goblins pending 时每次查询同一纹理两次；Goblins 入队拒绝后每次 update 重试 | 共用一次 `Texture::poll`，pending 不重交；provider 拒绝后退避 250 ms、已接收失败后退避一秒 | 更新回调计数覆盖单次 poll、拒绝退避、失败释放和最终 ready；UI 字体已有的单次查询／退避保留 |
| 双层新 ABI 插件的 viewport 不同，或普通窗口尺寸变化，触发全 renderer 重建、四个 shader 编译、插件 reset 和纹理重传 | 生命周期只比较 device/queue；后端仍逐帧校验尺寸并在 fence 完成后调整对应离屏槽 | 真实核心＋Minimap＋合法上层 DLL 交替尺寸，generation/reset/纹理创建均保持 1，真实绘制后驻留分配稳定 |
| GPU 未完成时调用 `wait_idle(0)` 仍创建事件并注册完成通知 | 零超时只查 fence；关停的真实有时限等待保留 | held-WARP 测试连续 1,000 次查询零事件，真实等待创建事件，完成后查询成功 |
| Minimap render 在检查 `FrameInfo.size` 前复制全表；缺少 texture_poll 的宿主仍能 init | 先读固定 size 字段，足够后才复制；把必需的 texture_poll 纳入现有 init 检查 | 短 header 紧邻不可读页面安全返回 ERR_INVALID；缺失 callback 返回 ERR_ABI，不创建实例 |

单图限制没有放宽，ABI 布局和版本未变。正常加载、暂未接收的请求、单块瓦片错误继续不显示全图文字；元数据／图集的真实错误继续显示并记录处理阶段。初次素材仍要求独立的实时地图／显示就绪，不重新绑定标记快照。

## 清理与边界

- 删除资源对象中额外保存的全局 status，直接从现有文件／解析错误推导提示。解析成功清除对应错误，不让已经恢复的 GFX 错误残留到目录等待阶段；真实归档素材的生产解析覆盖恢复路径。
- 预设借用现有 Settings Arc，删除每次 update 的 Preset 字符串复制。标记缓存只保留其实际使用的地图、目录、Roundtable 和 home 字段，不再复制 beacon/memo 向量；原缓存与上下文复核回归保留。
- 删除旗标 category 查询中仅用于诊断的重复 divisor 读取，使用已经校验的缓存值，不增加 OS 调用或额外失败条件。
- callback gate 内再次检查 accepting，防已经进入的离线 render 在 stop 之后重建状态。这是并发边界加固，未被认定为用户现场故障；调用者仍不得让最终 FreeLibrary 与导出调用竞争。
- 保留有用途的低频阶段／队列诊断、字节预算、取消及 fence／文件池 generation 退休机制。原生 PIN、STOPPED_RESIDENT=1 及需要重启进程后再加载的限制不变。

## 验证方法与范围

在仓库根目录执行 fmt、workspace check、all-targets/all-features clippy 和 workspace 测试；启用差分 feature 前先导出 C++ 基线并设置 `EROVERLAY_CPP_REFERENCE`，另外运行原 C++/Rust 真实内存差分与归档素材测试。Release 安装构建不链接差分 reader，也不包含测试插件或专用生命周期导出。下列数值是迁移前实测，不是新 Rust 扫描器的验收结果。

本轮实际结果：fmt/check/clippy 全部通过，workspace 106 项通过、零失败；游戏库 Release 差分 feature 32 项通过（含 28 项重叠的常规测试和四组 C++ 差分），两个性能基准跳过；归档 GFX／布局／四张 BC7 图集验证与解析失败恢复一项通过。Release workspace 构建通过，真实 DLL ABI 拒绝／回滚 11 场景通过。WARP 普通模式及合法上层模式各连续三轮通过；前者每轮 19 次消费层回调，后者本次每轮 48 次，后者 generation/reset/纹理创建各为 1，并有真实纹理绘制和 GPU 在途停止。

真实 DLL/WARP 检查有两种模式。普通安装包不含上层测试插件，只检查隐藏 Minimap、无消费者层、尺寸变化和装卸载。要检查真实 GPU 在途停止，在本工作树 `target/` 的独立测试目录中预置 `EROverlay.dll`、`overlays/Minimap.dll` 和 `overlays/BadPlugin.dll`，运行：

```powershell
target/release/eroverlay-harness.exe E:/absolute/test-package 3 0 E:/absolute/test-package/overlays/BadPlugin.dll
```

该模式由同一个正式插件加载器加载合法上层新 ABI fixture，提交真实纹理和三角形，覆盖不同层尺寸、驻留保持、GPU 门闩下的停止、卸载和重载。fixture 只存在于受控测试目录，不进入安装包。测试详情见源码中的 `crates/abi-fixture/README.md`。

本轮没有重跑未改动的 EXE 扫描、自动启动引用压力循环或整套 GPU 性能基准。已有扫描和 PIN 证据保留。这里给的是功能、所有权和工作次数证据，没有将它们换算成新的游戏 FPS、完整 C++/Rust 性能结论或 HDR／全部素材组合验收；新审查包尚无新的游戏内测量。
