## 完整逐项证据

[证据目录](evidence/boss-battle-audit-2026-11-02/) 内包含：

## 需要决定的范围

推荐先保留“一场战斗”的定义，补充场景有效性检查，明确列出早期退场、替代路线和后期再战；不承诺其结果恰为 207。兰斯桑克斯还需要把正常退场与替代击杀条件正确表达，不能继续将互斥 kill flag 都当必做进度。

如果要求恢复旧版 207 项的角色／进度范围，则需要另行同意：阿杜拉早场归入晚场旅程，兰斯桑克斯两条击杀路线按 OR 完成，帕奇再战归入初战记录；残留模板通过场景证据排除。这是范围和完成语义的变化，不是同场归并。最小方案可以只保留这几条有证据的外部关系，继续由 Param／事件发现目录；不需要恢复旧 207 项白名单或任何多语言名单。复活必须仍只使用已审查的外部配方，不能由合并关系自动推导新的写入。

另有独立边界：DLC 后门两名大树守卫各自 AI 触发、各自完成／获奖，但允许同时交战并共享最后横幅处理。旧版分别记录 `2050470800`、`2050480860`。按独立持久结算保留两项有事件依据；若用户将它们定义为一场，则旧 207 本身也需要减一，并明确双方 AND 完成、部分完成和逐只复活方式。共享 guards 或共享收尾不能代替这一决定。

`GameAreaParam` 的 207 个唯一旗标也不能直接用作目录：精确旗标关联只能保留 199 个事件项、覆盖 197 个旧成员；加入精确显示实体关系得到 204，再加入同地图精确行 ID 得到 208，仍漏旧版的落叶丹恩。Param 不是一个可直接得到正确 207 的白名单。

## 重现

先按 [导出工具](../tools/export_cpp_reference.py) 生成明确的 C++ 参考目录。普通构建不需要这些外部输入。

```powershell
python tools/audit_boss_catalog.py --reference target/cpp-reference --params target/research --events E:/Projects/EROverlay/build/ida/boss/events --output target/boss-battle-audit
```

Param 目录显式包含六张 `.param` 以及 `item_dlc02.bnd`、`menu_dlc02.bnd`；事件目录显式提供解压后的原始 `.emevd`。审计测试本身读取生产资源计划、生产事件读取器和生产归并函数，完整事件归档仅作覆盖核对。CSV／JSON 是审计产物，不参与 DLL 或默认配置。

独立复核场景反例可以使用已解压 MSB 与本机已有 SoulsFormats：

```powershell
./tools/audit_boss_scene.ps1 -Assembly <SoulsFormats.dll> -Scene <m60_38_54_00.msb> -Entity 1038540800 -Model c4680 -Output target/msb-check.json
```

此命令记录 reader／scene 哈希及实体结果，不会安装解压器或获取游戏文件。缺少外部资产时该项不冒充已执行。归档和受控测试均不能证明游戏现场的实际参战、复活或 FPS。
