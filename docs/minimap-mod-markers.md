# Minimap 的 Mod Boss 标记验证

2026-10-04。用户截图中，游戏大地图显示的 Boss 型赐福在小地图中缺失。已确认主要遗漏是独立的 `WorldMapItem/Cleared` 完成图层：小地图只绘制 `Icon_0`，没有读取完成事件或叠加骷髅图案。修复补齐完成图层，并同步赐福激活后独立地标的隐藏规则。验证使用 `test-data/mod` 的地图 GFX、图集布局、TPF 和完整 `regulation.bin` 参数。

前一轮修复了启动时过早缓存原版图标的风险，但用户确认更新后仍缺少图案，因此加载时序不能作为本次截图问题的充分解释。原来的验证只检查底图与存活图层，未检查击败后的完成图层。

## 已确认的资源和参数

Mod 的 `menu/02_120_worldmap.gfx` 包含 906 帧、151 个非空图标定义；原版基准为 348 帧。正式 GFX 解析器已经能够恢复新增帧，布局中的别名与 DDS 都存在，不需要添加外部图标或按 Mod 名称写死图案。

| 图标编号 | 图形内容 | 来源 |
|---|---|---|
| 499 | Boss 完成标记底图 | `MENU_MAP_WorldBoss` |
| 500 | Boss 底图与存活图案 | `MENU_MAP_WorldBoss`、`MENU_MAP_Boss_Alive` |
| 501 | 赐福与 Boss 存活图案 | `MENU_MAP_01_Bonfire`、`MENU_MAP_Boss_Alive` |
| 502 | Boss 型赐福与禁止传送斜线 | 两张位图与 GFX 矢量斜线 |
| 独立图层 `Cleared` | 击败后的骷髅，叠在赐福或地标上 | `MENU_MAP_Boss_Dead` |

图集资源与此前大型包修复使用的样本一致：70 张图片，解压后 325,120,600 字节。小地图需要四张图集，复制总量为 7,340,624 字节。新增 Boss 别名位于 `SB_MapCursor_03_dlc`，沿用按可见图标上传和闲置回收。

Mod 的 BonfireWarpParam 有 480 行，其中 142 行使用高编号替代图标；WorldMapPointParam 有 659 行，其中 146 行的基础图标为 499。这说明 Boss 标记同时存在于赐福与地标两类数据中，不能只为赐福强制叠加一张 Boss 图片。

例如黄金河马使用赐福行 210001 与地标行 210008，两行地图坐标相同。事件 21009850 控制 Boss 发现，21009851 控制地标切回基础图标；赐福完成事件为 21000850，地标完成事件为 21009852，72101 控制赐福激活。赐福激活前可显示地标 500 或 499；激活后独立地标的文本条件关闭，显示赐福图标 1 与完成骷髅。梅瑟莫的赐福行 210100、地标行 210108 使用同一结构。生产代码没有新增 Boss 专用编号判断。

## 完成图层与显示条件修复

Mod 的 `WorldMapItem` 在深度 1 放置 `Icon_0`，在深度 5 放置名为 `Cleared` 的子图层。`Cleared` 的子图形引用 `MENU_MAP_Boss_Dead`，缩放约 0.4，平移为 `(-31.2, -31.2)`。把它叠在赐福底图上得到的骷髅赐福与用户截图中的图案一致。原版同名图层是偏移 `(28.3, -22.4)` 的填充圆点。

通过 Python `idapro` 静态分析 Steam EXE，确认以下调用关系：

| RVA | 作用 | 实现对应 |
|---|---|---|
| `0x87BE10` | `WorldMapPinData::SetTo` 分别设置 `Icon_0` 和 `Cleared` | 基础图标与完成图层分开绘制 |
| `0x88C7A0` | 赐福构造函数从 PARAM `+24` 取得完成事件，`-1` 转为 0，保存到 pin `+84` | 读取 `BonfireWarpParam.clearedEventFlagId` |
| `0x87CA60` | 地标构造函数从 PARAM `+20` 取得完成事件，执行同样规范化 | 读取 `WorldMapPointParam.clearedEventFlagId` |
| `0x87BF90`、`0x87D230` | 普通地标需至少一项活动文本；范围型或允许无文本的地标可绕过文本条件 | 激活赐福后隐藏独立 Boss 地标 |

`SetTo` 只有在完成事件非零且已设置时才显示 `Cleared`。虽然 PARAM 注释把 0 描述为「已完成」，这个 UI 子图层的实际显示条件仍要求有效的非零事件；修复采用可执行文件逻辑。

GFX 解析器新增读取 `WorldMapItem` 子图层的方法，保留子图层局部矩阵与绘制深度。Resources 将完成图层加入解析及别名解析，Data 在原有标记刷新中保存完成状态，Renderer 在基础图标之后绘制完成图层。原版矢量圆点同时补齐填充渲染。

图层沿用当前 Mod 图集，没有新增纹理或常驻显存。完成状态随现有 200 ms 标记刷新读取，绘制线程只读快照。`Cleared` 作为可选装饰，缺失时不会阻止必要地图与玩家图标加载。

## 首次加载与路径修复

原实现从第一次更新就请求 GFX 和布局，并在解析成功后一直使用这份不可变定义。Overlay DLL 可以在 Mod 资源覆盖完成前启动，早期成功读到的原版 GFX 会被永久保留。普通赐福仍有定义，高于原版帧数的 Boss 图标则无法绘制。

修复后，首次元数据请求等待原生地图状态有效。游戏已有玩家、地图 view 和地图进度数据时才开始加载；解析完成后不增加逐帧资源检查。等待期间保留版本不受支持的提示，核心确认兼容后恢复等待状态。后续资源任务与并发发布方式保持原样。

me3 的加载流程先调用 `load_native`，再安装 `asset_hooks::attach_override`，因此 Overlay 启动不能单独作为 Mod 覆盖已完成的依据。源码参考：[mod-host/src/lib.rs](https://github.com/garyttierney/me3/blob/main/crates/mod-host/src/lib.rs)。首次加载等待覆盖了 Mod 挂载在进入游戏前完成的情形；运行中修改资源覆盖仍需要重启游戏。

静态分析使用 Python `idapro` 打开来自 Steam EXE 的已校验 IDA 数据库。GFX 高层加载函数 RVA `0xD7D5B0` 在文件读取前调用 `0x120EA0`，将虚拟路径中的 ASCII 大写转为小写，并将反斜杠改为正斜杠。原始请求层 `0x26F74D0` 只复制调用者路径，不承担这项规范化。核心 GameFiles 现在对虚拟路径执行相同转换；磁盘路径与 TPF 内 DDS 名称保留原样。

me3 与 YAFSML 的 VFS 也会规范化路径，因此不能把路径大小写认定为本次截图的原因。这项修改用于让核心请求遵循游戏的路径规则。分析对象为 Steam 安装中的 `eldenring.exe`，SHA256 为 `1a3547101327f65d0c76da2f9190ac0aa66871ea42bae2aecc61e11a8b597891`；没有挂断点或附加调试器。

只在启用资源日志时输出一次 `minimap-definitions frames=... recipes=... atlases=...`，用于区分读取了原版还是 Mod 的定义。`log_file` 留空时跳过格式化和日志回调，不增加逐帧日志。

加载时序是代码中确认存在的独立缺口，新增启动回归覆盖这一条件。用户反馈证明它没有解决完成图层缺失，本次原因结论应以 `Cleared` 遗漏为主。

## 验证

文件验证先提供原版启动 GFX，再在地图状态就绪后切换到 Mod GFX。正式 Resources 在启动阶段不发送元数据请求；就绪后通过 GameFiles 的请求、回调、查询与释放加载 Mod 定义，499～502 均可解析。虚拟路径回归另覆盖反斜杠、大写、磁盘路径保留和 DDS 名称大小写保留。

将同一文件验证程序链接到修复前的 Resources 后，程序退出码为 1，报告 `FAIL: metadata requested/cached before gameplay resources were ready`。使用修复后实现时验证通过。新增断言还确认图标定义发布后不再调用首次加载的地图状态探测。

额外对照记录了旧实现的实际缓存状态：地图就绪前已完成四个元数据请求，保留 118 个原版图标定义，图标 499 不存在；将文件来源切换为 Mod 并再次更新后，请求数、图标数和 499 缺失状态都不变。这复现了「后来资源已就绪，但新增 Boss 图标仍缺失」的代码路径。

`minimap_mod_marker_verify` 使用当前 Mod 的完整 PARAM、906 帧 GFX、布局和 DDS，连接正式 Data、Resources 与 ImGui Renderer。更新后的 11 个 Mod 场景分别检查底图、存活图案和完成骷髅 UV，覆盖发现、击败、赐福激活、旋转半透明圆形、分组开关、独立地标隐藏和禁止传送样式。追加 `--vanilla-completion` 的两个场景检查原版圆点中心被填充三角形覆盖，以及关闭赐福组后图案消失。

在补齐图层之前，新增断言明确失败：`FAIL: missing WorldMapItem/Cleared completion glyph from the actual mod GFX`。补齐后通过。历史布局回归另检查全部 28 个 profile 的完成状态变化，以及完成事件 0 和 `UINT32_MAX` 不显示图层。

验证程序读取本地解压资源并在自身内存中设置事件状态，不连接游戏，也不写入 Mod 文件或存档。GPU 提交在此回归中模拟，实际 D3D12 上传由现有纹理验证覆盖。原版、历史布局、死亡、编号、地图进度和性能回归继续保留。

Debug 与 Release 的核心及 Minimap 构建通过。11 项回归均通过，覆盖原生素材解析、地图数据、地图碎片进度、Mod Boss 标记、文件请求、动态图集、性能、28 个历史布局、死亡标记渲染、编号标记渲染和 D3D12 纹理上传。其中 Mod 完成图层有 11 个显示场景，原版完成图层有 2 个场景。验证结果不等同于用户存档上的游戏内验收。

本次首次加载等待位于 `Minimap.dll`，虚拟路径转换位于核心 `EROverlay.dll`。构建产物位于 `build/native/bin/EROverlay.dll` 和 `build/native/bin/overlays/Minimap.dll`。验收需要同时使用新核心和 Minimap，并重新启动游戏；未自动覆盖游戏或加载器中的 DLL。

本轮检测到的游戏经用户确认正在测试其他内容，未启用本次 Mod；该进程的采样不作为原因或修复证据，已停止采样。最终验收需要用本次 Mod 加载新 Minimap，在截图附近比较两张地图。`[markers].graces` 控制赐福及其完成骷髅，`landmarks` 控制激活前的独立 Boss 标记。
