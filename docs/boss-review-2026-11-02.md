# Boss 验收修复

本页记录首交提交 `bab88d3` 之后的四项修复。首交的数据覆盖、原生输入与生命周期证据保留在 [验证记录](boss-validation.md)，本轮仍未启动、注入或安装游戏。

## 紧凑模式只绘制状态

完整列表的行缓存仅在完整窗口打开时重建。紧凑模式继续消费更新侧准备的状态文字，不执行地区分组、行筛选和标题构造；待处理的 revision 和地图变化标记保留到展开。关闭窗口后再有进度更新，下一次展开直接显示最新快照。

回归调用生产 `Ui::render`，使用 95 组、211 行快照：多次紧凑 revision 更新后行缓存容量仍为 0；展开得到完整行和当前计数；再收起、改变进度和地图后，旧行缓存保持不动，重新展开刷新为新计数。测试不扩展生产 ABI，也不新增另一套地区索引。

## 批量读取共享树节点快照

`EventFlagCache::read_many` 在单批内共享 sentinel／root，以最多 4096 份 56 字节 OS 快照缓存节点及 packed 管理字段。重复遍历同一节点、读取 packed 的 stride／base 时使用本批快照，批次结束即丢弃；地址缓存的原 1 秒有效期及 manager 变化仍会清除本批快照。完成位字节仍按本批去重读取。

完整节点不可读时，回退到旧路径实际需要的单字段读取。跨页测试让 packed 节点最后四字节不可读，确认所需字段完整时仍能读取；direct 节点必需指针或 key 不完整时仍输出未知。另一回归覆盖新值、新分类、地址缓存到期、manager 切换、无效地址和循环树。Minimap 单旗标读取与复活前置解析继续使用原字段路径，没有改为裸指针读取或减少上下文检查。

与未修改的原 C++ `BossDataSet::update()` 的相同输入、布局、冷／热／隐藏和交替轮次对照见 [性能记录](boss-performance.md)。组件测量不代表游戏帧率或完整插件等价。

本机固定 CPU 0、Release、每组 1000 个样本及三轮交替测量中，207／211 冷更新由原先 5504～5975 次 RPM 降为 488～497 次，p50 由约 1.1～1.2 ms 降为 160～164 µs。热更新保持 292／296 次 RPM、约 66～67 µs，加载隐藏保持 18 次 RPM、约 3.5 µs。相同原 C++ 更新约 1.5～1.6 µs；安全 OS 拷贝、上下文校验和哈希查找的剩余差距仍然存在。

## 未知遭遇保留事件范围

已证明的完成旗标继续按旗标合并，支持共享进度的多 Boss 和多阶段。未知完成条件的键改为地图、运行变体和实体号；另一地图或变体复用实体号时形成独立条目，同一范围内同实体的多条生命条继续合并名称。未知条目仍显示 `[?]`，不计入完成比例，也不允许复活。

## 文本回退按所需命名空间判断

Item 任务需要 `NpcName` 和 `PlaceName`，menu 任务需要 `GR_MenuText`。合法 BND 只含其他 FMG 不再算作任务成功；缺失的命名空间转到对应 base binder，部分成功时只补缺失部分，保护已读取的 Mod 文本，包括 DLC binder 内的 base 层成员。

FMG 成员存在与文本条数分别记录。合法空 FMG、全 null 条目及合法空字符串不触发缺失回退；空字符串继续作为有效覆盖。base 仍缺少目标、解析失败或语言不可用时，目录保留数字降级，并标注部分游戏资源不可用。合法 BND 中的其他命名空间不能使任务提前完成。

复活配方、已有配置、`Challenge.txt`、ABI 和输入捕获规则未改变。升级仍需同时更新 `EROverlay.dll`、`overlays/Minimap.dll`，新增或更新 `overlays/Boss.dll`、`configs/boss.ini` 和 `configs/boss-revival.json`；保留其他现有配置与挑战记录。默认 `=` 展开／收起，`Esc` 或关闭按钮返回紧凑状态。

根目录 fmt、workspace check、all-targets clippy `-D warnings`、测试和 Release 构建通过：144 项常规测试通过，8 项需外部资源或测量输入的检查默认跳过。显式导出旧 C++ 后，all-targets／all-features clippy 通过；game 的 C++ 读取 fixture 51 项通过、6 项默认跳过，探针 1 项通过。真实归档目录回归仍得到 211 场、211 个完成旗标及 0 个缺失名称。
