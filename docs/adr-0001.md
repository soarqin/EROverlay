# ADR 0001：Rust 核心、egui 和 DLL 边界

状态：已实现；用户已在 1.17.2 确认功能和加载提示修复正常，累计审查包另有离线回归。完整同场景性能、HDR 和全部素材组合仍待验收。采用可逆选择，用户后续决策可在同一工作树调整。

## 范围与已明确的决策

首期改写核心基础库和 Minimap，保留独立 DLL 加载。Boss、Achievements 后续直接重写。旧插件不需要兼容；不引入 ImGui 桥接或旧 Rust ABI 假设。

性能以同场景的 C++ 实现为主要对照，计入整个 Rust + egui 路径的实际消耗。原先提出的固定毫秒目标降为观察参考，不是本版交付硬门槛，也不擅自补充固定百分比门槛。既有 C++ 瓶颈与 Rust 新增回归分别记录。

## egui 和 DX12 后端

锁定 `egui = 0.33.3` 和 `windows = 0.62.2`，并签入 `Cargo.lock`。已通过 `cargo info egui@0.33.3` 和本地 crate 源码核实接口。0.33.3 不是当前最新 egui；选择该版本是为了固定经过实现和测试的 API，升级需要重跑纹理、像素和生命周期检查。[egui 官方文档](https://docs.rs/egui/0.33.3/egui/) 说明自定义集成通过输入、纹理更新与 tessellated primitives 连接后端；[windows-rs](https://github.com/microsoft/windows-rs) 提供 Windows/DX12 的 Rust 接口。

使用专用 DX12 网格 renderer，不引入 winit、eframe、独立窗口或 swap-chain 循环。现有 UI_SCENE 已提供借用的 device、queue、RTV、格式和 viewport，专用后端可以直接沿用原生队列和合成语义，避免为通用窗口框架增加输入和呈现路径。

Minimap 私有持有 egui context。核心持有 DX12 renderer、GPU 纹理、提交环、descriptor 和 fence。插件将 egui 结果转换为稳定 C 网格描述；核心复制顶点和索引，限制单帧总量，随后上传到复用缓冲。不存在跨 DLL 传递 egui context 或释放对方 Rust 容器的情况。

原生队列的上下层回调共用 `sequence`。每个插件只属于一个渲染层，其私有 egui context 在同一 renderer 世代、同一队列序号下最多推进一次；核心分发与 Minimap 入口都检查重复序号。输入边沿只由 update 线程采样，render 不再次消费输入。不同层不会重置同一队列的纹理提交预算。

## 原生 UI_SCENE 与复用边界

Rust renderer 实现顶点/索引上传、shader、PSO、纹理、离屏、透明度、形状裁剪和合成。Minimap 在游戏 UI 下层；ABI 保留未来上层插件能力。下层先绘制 RGBA8，再按游戏 UI 剩余透过率合成：`ui.rgb += lower.rgb * ui.a`、`ui.a *= 1 - lower.a`。主目标按已验证的 RGB10A2 支持，不增加未经验证的格式。

每个插件的组独立合成。下层以加载顺序的逆序提交，抵消“新组放到已有组背后”的合成方向；上层保持加载顺序。两者均使后加载插件覆盖先加载插件，不改变 Minimap 内部的原生标记顺序。

四个 GPU 提交槽仍由各组共享。下层提交须为每个已加载上层组保留一个空闲槽，最多保留三个；此规则恢复 C++ 对上层的保护，防止下层占用最后空槽后 Boss 丢帧。保留上限避免更多上层插件使下层永久饥饿；超出槽数的工作仍按非阻塞策略跳过，不等待 GPU 或扩充槽池。复现和受控双插件验证见 [菜单预加载与层级修复](boss-menu-layer-fix-2026-11-02.md)。

PE、签名、RTTI、unwind 和调用关系验证由 Rust 扫描器承担，以独立 C++ 基线 `master` 的 `afab7e1` 规则及归档证据核对。小型 C++ 适配层只处理游戏 UI_SCENE 原生队列 hook 契约，并编译 `third_party/minhook/` 的 C 源码。旧 C++ 工程和扫描器不保留在本分支，也不链接旧核心、gamefiles、renderer、Minimap 或 ImGui。显式差分测试所需的旧 reader 从外部基线导出，见 [源码布局](source-layout.md)；安装构建不编译该 reader。

游戏文件请求、回调所有权、地图状态、事件标志、PARAM、DDS/TPF/BND 与 Minimap 数据/绘制由 Rust 实现。游戏负责其原生虚拟文件请求的解压和 allocator 回收，Rust 不使用自己的 allocator 释放游戏缓冲。

## 线程和生命周期

`DllMain` 只禁用线程通知并创建初始化线程。扫描、配置、I/O、插件加载和 hook 安装在 loader lock 释放后进行。初始化失败清理已创建对象，不重复扫描 EXE。

update 线程以约 60 Hz 采样游戏状态和输入，处理文件任务及 Minimap CPU 数据。纹理准备线程解析 DDS，保留压缩格式与 mip 层；原始 RGBA 在此准备预乘透明度。render 从原生同步队列回调进入，借用当前 RTV，不持有 back buffer。插件通过不可变快照和非阻塞读取交接数据；核心遇到 update 或资源锁忙时跳过工作。

renderer 生命周期只依赖 device/queue。viewport 变化由后端在 fence 完成后调整对应槽的离屏目标，不使插件、shader 或驻留纹理失效。设备或队列变化时，旧提交未完成就跳过帧；零超时 fence 查询不创建事件，不能在游戏 render 线程等待 GPU。重建和 renderer reset 排除插件 update。正常停止先拒绝新工作、禁用 hook 并排空对桥接上下文的访问，再停止 update、等待已提交 GPU 和文件回调退役，最后销毁插件与运行资源。超时返回 busy 并保留代码和回调上下文，不能释放仍在被游戏使用的内存。

2026-11-02 的卸载审查确认：detour 线程可能停在读锁前或释放读锁之后，此时停止可以完成，线程仍需要核心代码。MinHook 的指令指针修正不排空整个 detour。选择在首次启用原生 hook 前固定所属模块，直到进程退出；这也保护部分安装失败后的尾声。`STOPPED_RESIDENT = 1` 表示停止完成但代码常驻，外部加载器可以释放自己的引用，不能宣称模块已卸载。再次启动原生运行需重启进程。没有安装 hook 的离线模式维持 `OK = 0` 和完整装卸载检查。替代方向是建立可证明覆盖完整机器码入口/返回区间的卸载协议；本期不为此引入手写跳板或固定 sleep。生命周期保证不包含运行中替换 DLL。

[Windows 官方 `GetModuleHandleExW` 文档](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulehandleexw) 明确 `PIN` 的模块保持加载直到进程结束，调用 `FreeLibrary` 不会解除固定。本期用这一平台保证保护 detour 代码；它不替代回调上下文和 GPU／文件对象的退役同步。

资源预算继承现有 C++ 规则：瓦片缓存目标 64 MiB；CPU 待上传数据总量 64 MiB、单张 32 MiB、最多 768 个用户纹理 token；update 和同一游戏队列的 GPU 提交分别最多四张、约 4 MiB；全体提交槽的在途上传暂存目标 16 MiB、最多八张。超预算的单张只在队列空闲时独占，避免饥饿；不为腾出预算而等待 GPU。

CPU 待上传计数覆盖输入任务、已准备数据和已转交 renderer 的源字节，阶段转移不退还额度；最后一个所有者释放源数据后再退还。GPU 上传暂存按实际分配另计，包含行距和 heap 对齐。

每个新 ABI 的导出都明确借用、长度、线程和所有权。Rust 回调在 FFI 边界捕获 panic；不使用跨 DLL unwinding。`unsafe` 限于 Win32/COM、原生游戏 ABI、受控指针读取和网格借用，并记录调用不变量。

## 验收证据的边界

静态 EXE 扫描证明签名和布局契约符合解析器，不证明真实游戏版本一定正确渲染。WARP 像素测试证明指定 fixture 的 GPU 行为，不代表 RTX 或游戏帧耗时。DLL lifecycle harness 证明独立进程中的加载、回调和释放，不替代游戏内退出验证。

本期必须保留功能对照表，缺失项注明原因、当前替代和下一步。游戏内场景与同场景 C++ 对照缺失时，不能宣称完成性能验收。

## 2026-11-02：Boss 与交互扩展

Boss 使用独立的 `Boss.dll` 和私有 egui context，属于游戏 UI 上层。`crates/ui` 静态复用字体、输入事件转换和网格提交工具，Minimap 继续持有自己的 context；没有新增公共 UI 服务 DLL。字体只嵌入 Ubuntu Light，其他语言沿用系统或自选字体。

Host V1 的原 176 字节前缀保持不变，末尾以 size 和能力检查追加 UI 输入及 Boss 状态服务，完整表为 224 字节。Minimap 只复制原前缀，Boss 要求完整表和新增能力。跨 DLL 仍只传 POD、显式长度和函数指针。每个插件在同一原生序号最多推进一次 egui，上下层继续共用核心上传预算。

2026-11-03 为 Boss 切区折叠追加可选 `read_boss_region(user, context, out)`，完整 Host 表为 232 字节；原 Boss 状态前缀固定为 224 字节，`BossState` 仍为 32 字节。Boss 固定复制旧前缀，仅在尾部完整存在时读取函数指针，再以 `CAP_BOSS_REGION` 门控；224／228 字节短表不半拷或越界读取。服务只在 update 侧复用 FieldArea 动态定位并验证当前上下文；Minimap 继续仅复制 176 字节。地区、布局及真实短表验证见 [地区修复记录](boss-layout-regions-2026-11-03.md)。

交互路由只在原生模式发现交互插件时安装。窗口消息及 DirectInput 键鼠读取按完整列表的短期捕获租约门控；紧凑状态、隐藏、失焦、加载、全屏地图和停止释放捕获。拖动的 Win32 mouse capture 由窗口线程取得和释放；render 仅请求取消。已固定的核心保护仍可能在执行的 detour 和 WndProc，停止不解除原生代码映射。控制器不交给本期 egui 界面。

Param、事件和 FMG 在更新侧生成有界缓存；稳定绘制只消费快照。具名大生命条以 EMEVD 启用指令为证据，Param 提供资源地图和位置，不能把名字或卢恩字段视为 Boss 判定。辅助复活旗标继续放在外部配置。可核查例子和限制见 [Boss 数据来源](boss-data-sources.md)、[事件记录](boss-events.md) 和 [验证记录](boss-validation.md)。
