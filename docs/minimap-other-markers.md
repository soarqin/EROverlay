# 小地图其他标记与 Map for Goblins 验证

2026-10-14。新增 `[markers] others`，默认 `false`。开启后显示 NPC、手动图章和地图 Mod 添加的其他地图点；与赐福、地标、死亡和编号标记的开关独立。中英文配置、说明和更新日志已同步。

## 显示规则

普通地标组保持不变：原版 9 个剧情目标点（图标 87、88，编号均不低于 78500）旧版本就随地标显示，现在仍跟随 `landmarks` 开关。原先排除的低编号地图点和 NPC 图标（80）归入其他标记组。关闭时跳过这一组的事件状态处理和手动图章读取，渲染器同时过滤已经发布的快照。开关变化会使标记缓存失效。

游戏 `WorldMapPointPinData::IsOpen`（当前 Steam EXE RVA `0x87D340`）把开启事件 `0` 和 `UINT32_MAX` 视为无条件开启。`Map for Goblins` 大量地图点使用事件 `0`，通过活动文本槽的开启、关闭事件控制类别、拾取和击败状态。实现沿用这些条件，并支持基础图标为空时使用有效的替代或远眺图标。没有按 Mod 名称固定图标图案。

手动图章读取原生 `MemoList` 对应的保存列表，最多 100 槽，保存记录使用图标帧 1～10。更新线程复制并复核记录、容量和计数，出现并发修改时丢弃该次采样。图案从当前地图 GFX 的 `Body/_/Base/MemoList/Item_0/Icon_0` 读取，跟随保存的地图层、坐标和删除状态。

## 图标兼容

用户提供的 `Map for Goblins v1.17` 包含 376 帧地图图标、6,917 行地图点参数，比原版增加 6,445 行。大部分新增地图点使用低编号，新增图标复用原生图集中的素材，并添加颜色变换。

现有解析器会拒绝非默认颜色变换，以及该 Mod 第 371 帧使用的图层混合模式。修复后解析并组合颜色乘数与加数，保留矢量图案颜色；混合模式 0～2（普通与图层）按普通合成处理；位图只解码需要变色的图标区域，每个压缩块只解码一次，生成缓存的 RGBA DDS。未经变色的图标继续使用原生压缩图集。`bcdec` 采用固定版本的 MIT 许可代码，分发包包含其许可证。

变色工作在更新线程首次读取图集时完成；渲染线程沿用异步纹理上传和闲置回收。区域超出图集等无法变色的图标与越界的普通区域一样不绘制，不会每 3 秒重新读取整个图集容器。该样本产生 18 个变色图标，共 1,174,520 字节 DDS。核心 DDS 解析器增加 RGBA 格式支持，因此需同时更新 `EROverlay.dll` 和 `overlays/Minimap.dll`。

## 验证结果

- `minimap_settings_verify`：真实 INI 的默认关闭、显式开启、非法值回退和省略配置。
- `minimap_map_verify`：NPC、低编号点、剧情目标点不受 `others` 开关影响、基础图标为空时的替代图标、状态消失、缓存失效、图章第 100 槽、异常计数和无效帧。
- `minimap_mod_marker_verify --other-markers`：使用实际 Mod 参数、GFX、原生布局和 DDS，覆盖 30 组图标、50 个位图图层、28 个消失场景，以及 10 种手动图章；该样本中编号不低于 78500 的剧情目标点仍为普通地标。另使用原版参数和 GFX 验证 NPC 和全部图章，以及两类剧情目标点仍为普通地标。
- `verify_minimap_other_colors.py`：独立解码原生 BC7 图集，逐像素比较全部 18 种变色结果，包含正负颜色偏移、截断和透明度保留。
- `minimap_texture_verify`：通过正式核心代码上传生成的 RGBA DDS，实际 D3D12 回读与每个输入像素一致，并验证帧同步和描述符回收。
- `minimap_compatibility_verify`：28 个历史布局、短参数行、六种参数目录格式、赐福选择、死亡记录和稀疏编号标记槽均通过。
- `minimap_death_render_verify`：死亡标记、圆形与旋转、位置、边框和预设切换均通过。

Release 核心和 Minimap 构建通过。验证使用本进程中的模拟游戏状态与本地素材，没有连接游戏进程；用户存档上的实际显示仍需游戏内验收。使用 Mod 时，还需在其赐福菜单中开启相应类别。

样本 `regulation.bin` SHA-256：`e6c66eff33bb6b4bfc0040651c688220b305b4bc929405d2ef12d7964524a6b8`；地图 GFX SHA-256：`852a709fd48c9452b99d43e5cef6294a4c328766ca417edf63224942a1c9f1a8`。解包素材、转换结果和验证日志保存在忽略目录 `build/native-checks/`。

## 层级与启动加载补充

Minimap 使用游戏实际渲染顺序；游戏自身的遮挡不额外调整。2026-10-15，用户确认自己的 Map for Goblins 在游戏内渲染正常。

原版与本地 Map for Goblins GFX 的 `Body/_/Base` 使用以下容器深度。Minimap 从实际加载的 GFX 读取顺序，Mod 改变容器深度时也采用修改后的顺序。`others` 只控制显示，不构成独立层级。

| 深度 | 原生容器 | 内容 |
|---|---|---|
| 14 | `AreaList` | 范围型地图点 |
| 18 | `ItemList` | 普通地标、NPC 和 Mod 地图点 |
| 20 | `WarpList` | 赐福 |
| 26 | `MemoList` | 手动图章 |
| 28 | `MarkerList` | 编号标记 |
| 32 | `Dead` | 未回收卢恩 |
| 34 | `Player` | 玩家 |

本次分析的 Steam EXE 中，`0x9C7510` 按 PARAM 顺序构建地图点并分配到范围型或普通容器；`0xD5A540` 取得递增编号的参数范围。`0x74C0D0` 在模板的同一子对象索引插入复制的 `Item_i`，较早的地图点位于较晚地图点之上。因此 Minimap 在更新快照时将地图点按编号递减排列，再按 GFX 容器顺序绘制。通常只需反转已经递增的地图点；乱序参数回退到排序。没有按 Boss 图案、Mod 名称或 `others` 类别设置置顶规则。

固定资源路径改为游戏使用的小写形式，如 `menu:/02_120_worldmap.gfx`。现行核心已有路径规范化；Minimap 也直接提交规范路径，避免依赖旧核心替它改写路径。启动回归使用原样转交请求的文件接口，实际加载 Mod GFX，检查新增帧。

补充回归已通过：

- 原版与 Map for Goblins 的真实 GFX、布局、DDS 和完整参数回放。
- 地标、低编号地点副本、Mod 图案和赐福同位置显示；交换地图点编号后，图案按原生顺序改变上下关系。参数目录递增和乱序两种情况都得到相同的渲染顺序。
- 对本地 GFX 副本交换 `ItemList` 和 `WarpList` 深度，以 `--other-markers --grace-below-items` 检查赐福随素材改为下层。
- 28 个历史布局，以及死亡、编号快照、圆形、旋转和窗口位置回归；Release 构建通过。

如其他 Mod 组合出现图标缺失，可在 `minimap.ini` 的 `[diagnostics]` 中设置 `log_file` 并重新加载 DLL。`minimap-definitions` 记录 GFX 帧数和可用图案数；`minimap-markers` 记录 `others` 实际值、参数行数、通过显示条件的地图点数和其他点数，以及缺失图案数。仅刷新地图点快照时统计，并跳过未变化的计数；关闭诊断日志时不执行统计。此本地样本的基准为 376 帧、6,917 行，合并其他 Mod 后不能直接套用这两个数值。
