# Minimap 历史版本适配开发计划

依据[全版本分析报告](minimap-version-compatibility.md)和[逐 EXE 证据](minimap-version-compatibility.evidence.json)，目标是让本次新增的原生素材、地图碎片同步、死亡标记、编号标记和全开底图覆盖用户提供的 27 个独立旧 EXE。1.13 与 1.13.2 共用适配信息。

截至 2026-10-02，第 1～5 项开发已完成，Debug/Release、全部已核对哈希的离线布局回归和 12 图集验证通过。最新版此前已通过用户游戏测试；本次新构建尚未部署，逐旧版游戏和旧资源包测试仍待执行。

用户确认旧版不会请求 DLC 图标，因此旧版缺少 DLC 图集不作为开发阻塞。另要求兼容超过三个图集的 mod；实际清单不固定名称和数量，并已验证一次加载 12 个图集、117 个可见图标的正确纹理/UV 和回收。

| 项目 | 执行结果 | 验证 |
|---|---|---|
| 1. 逐 EXE 地址与文件接口 | 完成：27 个旧哈希 + 最新基准，共 28 条 | 28 个旧目录与最新 EXE 的哈希/入口/地址核对；正式回调与未知 EXE 拒绝验证 |
| 2. 地图、死亡与编号布局 | 完成：三类 menu/view 偏移，经 size-gated 接口传递 | 每条布局进入正式读取，覆盖死亡清除、编号空槽、菜单变化和上下文失效 |
| 3. 赐福与参数 | 完成：早期两组图标、后期四组；有界行读取 | 保护页短行、六种 PARAM 目录、normal/forbidden/alternate 和事件存储回归 |
| 4. 动态图集与地图类别 | 完成：超过三个图集、逐项发布；旧版只要求 M00/M01 | 12 图集一次提取、正式 Renderer 的 117 个可见图标、重复别名、失败隔离与重建；12 张真实 GPU 回读一致 |
| 5. 全开底图 | 完成：保留局部掩码覆盖、按版本筛选地图 | 正式 Renderer 的早期/中期地表和地下全开及恢复真实进度；无 M10 资源验证 |
| 6. 组合验收与支持说明 | 构建、离线/合成回归和文档完成 | 对应旧资源与旧游戏的逐版本实测待执行 |

## 1. 让文件与地图接口识别每个已核对的 EXE

用户随后要求后续游戏更新无需重新生成 game profile。长期接入改按[通用扫描方案](minimap-scanner-design.md)执行：本节逐哈希表保留为当前实现与回归基准，后续由共享特征、动态布局和 ABI 校验产生绑定信息。通用扫描原型已通过 28 个独立 EXE，DLL 接入尚未执行。

在 [GameFiles](../src/gamefiles.cpp) 中增加按完整 SHA-256 选择的版本信息。将 submit、flush、enqueue、cancel、manager、allocator、retire owner、菜单、GameData、参数仓库、事件仓库和 reveal 字节移入该信息，不在各函数中散布固定 RVA。

每份信息保留已核对的入口字节或指令签名。仅当文件哈希、入口和必要地址一致时启用；未知 EXE 继续显示明确状态。逐版本表由本次证据生成并人工核对，不能使用一个统一地址偏移量。

交付结果：文件桥能识别 27 个旧哈希与最新基准，并按对应地址提交、取消、释放和排空；诊断日志记录选中的版本信息。

验收：对目录中每个 EXE 离线检查表中的地址和入口；验证未知哈希不调用游戏函数；保持独立请求、原 allocator 释放和 callback 返回后退休规则。

## 2. 按旧版布局读取地图、死亡与编号状态

将菜单 owner、地图 view、MenuInfo 和 screenState 偏移加入版本信息：

| 范围 | menu→owner | owner→view | screenState |
|---|---|---|---|
| 1.02～1.02.3 | `+0x78` | `+0x248` | `+0x718` |
| 1.03～1.10.1 | `+0x80` | `+0x248` | `+0x728` |
| 1.12～1.17 | `+0x80` | `+0x250` | `+0x730` |

保留已确认通用的 view 玩家/死亡字段和 `view+0x338` 标记保存指针。继续对地下状态读取 U8，保留状态双采样、上下文 generation、空槽不重编号和正常上限五个标记。旧版不初始化 m61 时，不将未初始化转换器当作 DLC 坐标。

交付结果：每类旧版均能取得有效地图快照，死亡和编号标记使用相同绘制路径；配置继续为 `death_marker=1`、`player_markers=1`。

验收：扩展现有[地图快照](../tools/minimap_map_verify.cpp)和[标记绘制](../tools/minimap_marker_render_verify.cpp)验证，用三类布局检查死亡有效/清空、两个真实编号、空槽和编号 1～5；菜单切换、读档或指针变化时不保留旧标记。

## 3. 读取正确的赐福记录和参数字段

在 [Data](../src/minimap/data.cpp) 中按版本选择赐福 stride、normal 状态偏移和可用 Icon 数据：1.02 系列使用 `0x2D0/+0x2C8` 与两组图标；1.03 起使用 `0x350/+0x348` 与四组图标。

参数表读取先确认目录格式位和行边界。1.02 系列按该版本实际存在的字段读取，不能把整行解释为后续的 256/236 字节 C++ 结构；不存在的 alternate 图标和第二组条件按原生旧版行为处理。其他版本保留已确认的 alternate 条件。BonfireWarpParam、WorldMapPointParam、WorldMapPieceParam 和 GameSystemCommonParam 组号继续使用 `43/87/88/141`。

交付结果：旧版赐福、地标和图标别名选择正确，短参数行不会越界；异常资源给出具体参数和格式信息。

验收：读取相配套的旧参数文件，确认行 span、icon 字段和事件条件；回放早期两图标、后期四图标和 type 1/type 2 事件存储。

## 4. 按游戏实际资源加载图集和地图类别

调整 [Resources](../src/minimap/resources.cpp)：从布局 `imagePath` 和 GFX 所需图层构建图集清单，按内部 TPF 名称加载实际需要的 DDS。加载旧版没有的 `SB_MapCursor_03_dlc` 时，不能令地表、地下、死亡与编号图标整体失败。

地图索引至少要求当前版本使用的类别，按 EXE 能力与归档内容启用 M10。M00/M01 仍按原生地下叠地表方式绘制；缺少当前必需地图应报告具体类别。核对 WorldMap GFX 的版本、Player/Dead/Home/MarkerList 和 Text_0 路径；必要时遵循引擎已经确认的 Win 路径与 fallback 顺序。别名始终来自内部 GFX/TextureAtlas。

交付结果：DLC 前旧资源可以独立加载；最新版仍恢复全部已核对图层，不重新引入外部 `data/map`。

验收：用各历史资源包记录实际图集名、GFX header/帧数和节点；检查被引用图层无缺失、无外部 sprite，DDS 上传和延迟回收回归通过。

## 5. 让全开底图覆盖旧版实际存在的地图

保留 [Renderer](../src/minimap/render.cpp) 的局部 `UINT32_MAX` 覆盖，只对启用的地图类别选图。逐资源包核对每个 exists L0 瓦片的 allowedMask 全开变体，确认 fragment mask 与 XML 目录匹配。`full_map=0` 继续跟随真实碎片状态。

交付结果：全开选项在旧版地表/地下及 DLC 版本的 M10 生效，游戏快照、赐福发现条件和存档保持真实值。

验收：同地点切换开关检查请求后缀与底图；覆盖碎片未获得/已获得、地表/地下、旋转模式。L1/L2 继续保持未开放；1.02 的旧跨度单独确认后再考虑开放。

## 6. 完成旧版组合验收并更新支持范围

先编译 Debug/Release 并运行已有文件桥、地图、标记、GPU 上传与 fence 验证。离线核对全部 28 个目录；对旧游戏的实际测试使用相配套的 EXE 和资源，覆盖死亡未回收/回收、编号放置/删除/到达、碎片变化、全开开关、读档、旋转与卸载。

每份哈希记录「静态已确认」「资源已确认」「游戏测试结果」，不能用代表版测试代替全部旧版已测试的声明。需要游戏切换的验收安排到当前游戏正常退出后，测试过程继续遵守 Arxan 禁用断点和调试器附加的约束。

交付结果：README 和各相关 CHANGELOG 明确支持的 EXE 哈希/版本范围与尚未验收项；只有完成资源和对应运行验证的版本才标为完整支持。

## 当前输入缺口

本次开发不再因旧版缺少 DLC 图标而等待输入。对应旧版本的 GFX、`01_Common`、MapTile 和参数文件不在提供目录中；已完成动态发现与边界保护，且使用最新资源、预 DLC 资源删减和合成旧布局通过验证。这不能替代逐旧资源包的实际内容及游戏画面验收。L1/L2 保持未开放。新 DLL 仅写入构建目录，未更改 Steam EXE、存档或部署文件，也未提交。
