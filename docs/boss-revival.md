# Boss 复活配置与逆向证据

Boss 复活同时恢复主击败 flag、战斗阶段、场地物件、召唤物和入口状态。`flag_id` 仍是击败计数的唯一依据，`revive_flags` 只在复活时写入。2026-10-07 的数据覆盖全部 207 个已列入覆盖层的 Boss，包含 42 个 DLC Boss；169 个 Boss 配置了额外 flag，共 955 项，其中 10 项恢复为 `1`。14 种语言使用相同的配置。

## 使用方法

将 `configs/boss.ini` 中的 `allow_revive` 设为 `true`，重新启动游戏。在完整 Boss 列表中点击已击败 Boss 的勾选框，确认复活后，传送或重新加载场地。角色、碰撞、雾门、场景物件和事件线程需要由游戏重新创建；仅修改 flag 不会立即重建已经加载的角色。

复活界面会提示帕奇、红狮子城祭典、弗尔桑克斯梦境和丹恩对战的特殊行为。弗尔桑克斯和丹恩的入口 flag 恢复为 `1`，会在对应地图重新加载后触发原始传送事件。

## 数据格式

每个 Boss 的主 flag 保留在 `flag_id`。`revive_flags` 可以包含整数和带布尔值的对象：

```json
{
  "boss": "Godrick the Grafted",
  "place": "Stormveil Castle",
  "flag_id": 10000800,
  "revive_flags": [
    10000801,
    10000802,
    10002802,
    10002805,
    10002806
  ]
}
```

整数项表示清为 `0`；`{"flag_id": 9411, "value": true}` 表示恢复为 `1`；`value: false` 与整数项等价。ID 必须是 `1` 到 `4294967295` 的整数，`value` 必须是布尔值。相同值的重复 ID 合并，冲突值、非法 ID 或将主 flag 恢复为 `1` 会禁用该 Boss 的复活。未提供 `revive_flags` 的旧数据仍按主 flag 复活。

点击复活时，覆盖层重新解析所有地址，确认游戏处于存档内、主 flag 表示已击败，且解析期间 flag 管理器未变化。任一配置 flag 不可用时，整次操作在写入前结束。成功时先写额外 flag，最后清主 flag；逐位修改保留同一字节的其他 flag。击败计数同步减少，不把辅助 flag 计入成绩。

每次更新也重新解析主 flag 地址，避免读取旧存档的缓存地址，并重试初始化时尚不可用的 flag。共享 API 的类别查找要求精确匹配，同时支持原生的打包存储（type `1`）和直接存储（type `2`）。逐位写入使用原子操作，但不会暂停游戏的事件解释器。

## 证据来源与范围

[机器可读证据](boss-revival.evidence.json)保存每个 Boss 的主击败写入、入口判断和额外 flag 的操作数证据，并记录 IDA 指令地址、字节、文件哈希、事件 ID、调用槽位和参数补丁。每个 Boss 的 `witnesses` 数组保存去重后的证据，`primary_evidence`、`entry_evidence` 和每个 flag 的 `evidence` 是数组索引。

研究使用 Python `idapro 0.0.10` 调用 IDA 9.4，读取本机安装的 `eldenring.exe` 与原始 `Data0`，未修改游戏文件或存档。样本为应用版本 `1.17.1`、PE 文件版本 `2.7.1.0`，EXE SHA-256 为 `1a3547101327f65d0c76da2f9190ac0aa66871ea42bae2aecc61e11a8b597891`。提取了 588 个 EMEVD 资源和 4 个原始 flag 分配表。完整脚本、反编译文本、公开归档密钥和 IDA 数据库保存在忽略目录 `build/ida/boss/`。

| 原生函数 VA | 已核对的行为 | 对复活配置的作用 |
|---|---|---|
| `0x14056CAD0` | `2003[66]/[69]` 的 type、ID、状态位于 `+0/+4/+8` | 区分事件实体 ID 与 flag 操作数 |
| `0x1405842B0` | type `0` 使用绝对 ID，type `2` 加实例完成 flag | 正确展开事件槽位引用 |
| `0x140584250`、`0x140584030` | 正数槽位加到事件 ID；事件结束会写完成 flag | 识别有实际用途的完成状态 |
| `0x140CE26F0`、`0x140CE1850`、`0x140CE18A0` | 按整个资源的事件/指令顺序，收集并去重 opcode `6` 的参数偏移 | 公共完成 flag 使用该向量序号，不能用事件内指令编号 |
| `0x140575700`、`0x1405CBC70`、`0x1405CC060` | 公共事件使用槽位 `-1`、运行时地图 variant、bank `5` 和调用序号模 `1000` | 计算 AI 初始化和公共事件的真实 flag |
| `0x140588EC0`、`0x1405844C0` | variant `0/1/2` 分别运行 `0/50`、`100/150`、`200/250` 构造事件，并传给子事件 | 覆盖拉塔恩、火焰巨人、玻列琉斯等不同地图层的事件 |

| `0x1405FA250`、`0x1405FAA40` | 精确类别查找、type `1/2`、高位优先的位掩码 | 修复旧 API 对不存在类别和直接存储的处理 |
| `0x1405D3670`、`0x1405CE3F0`、`0x1405CE550`、`0x1405CB000` | flag 分配表、地图 bank 和 372 条本体到 DLC 的存储别名 | 排除没有实际存储的事件编号 |
| `0x140571370`、`0x14057B690` | 对话回复 flag 位于参数 `+16/+20/+24` | 恢复对话选择产生的本地战斗状态 |

生成器从已实例化的击败事件、雾门、战斗启动、阶段和召唤辅助事件追踪 flag。编号范围只约束候选项；每个实际配置项必须有原始脚本操作数或完成事件的证据，并通过原生分配类别检查。只在战斗读取或明确复活用途支持时清除完成 flag，不把整段相邻编号写入配置。

原始脚本中出现 flag 只能证明引用关系。复活的目标值是依据分支、初始化与战斗转换重建的值，不是逐个 Boss 战前存档的实测值；证据用 `target_is_reconstruction: true` 保留这一边界。

## 共用场地与支线边界

- 拉塔恩与红狮子城双人战共用祭典状态，复活一方会改变另一方的场地模式。不会清另一方的主击败 flag。拉塔恩的全局击败／陨石进度 `9130` 保留；`1051369360` 是重开祭典的本地对话门，杰廉后续支线已改变时仍需游戏内确认入口。
- 帕奇的战斗初始化会在 `3683` 或 `3691` 保留时重新设置击败状态，因此需要恢复存活和蒙流位置。`common:3699` 还读取其他地点的支线 flag；本次没有完整回退他的全局支线，后期存档需要实测位置是否维持。
- 尤弥尔的入口仍要求梅缇尔已击败。若先复活梅缇尔并保留她存活，应先再次击败梅缇尔，再进入尤弥尔战斗。部分支线入口还依赖 ESD 对话状态，本次未对 ESD 做全量重建。
- 死龙与丹恩使用原始事件入口恢复战斗，不回退整条 NPC 支线；对应地图重载可能自动进入特殊场地。
- 兰斯桑克斯会同时恢复较早遭遇的死亡/撤退状态；贝勒清埃贡的本地召唤和战斗对话位，保留全局召唤权限。
- 其他奖励、赐福、结局和世界进度保持既有状态。击败奖励是否再次发放由原始事件决定。复活场地不代表恢复首次战前世界或允许重选结局。

## 复现研究与验证

在仓库根目录运行以下命令。需要可用的 Python `idapro`、已授权的 IDA/idalib，以及 `cryptography`；解压使用已安装游戏的 Oodle 库。`--revival-baseline` 的地址适用于上述 EXE 哈希，游戏更新后应重新定位原生函数。

```powershell
python tools/ida_boss_research.py --revival-baseline
python tools/boss_event_extract.py
python tools/generate_boss_revival.py --apply
python tools/collect_boss_revival_evidence.py
python tools/verify_boss_revival.py
```

`boss_event_inspect.py --emedf <path>` 可选加载 EMEDF，为原始 opcode 提供可读名称；复活生成依赖原始参数字节和 IDA 语义，不依赖第三方 Boss flag 清单。生成器会先核对 EMEVD 哈希和分配表。`gen/revival.json` 是所有语言的共同生成源；重新执行翻译生成时保留主 flag 和 `revive_flags`。

离线验证包含所有语言/生成源一致性、原始事件调用链/槽位/地图层、参数补丁和操作数复核、每项 flag 的原生存储类别、分配表与别名表哈希、禁止清除其他 Boss 主 flag、真值标记，以及模拟内存中的正式 C++ 数据加载与复活函数。C++ 检查从 Visual Studio x64 Native Tools 命令行运行：

```bat
tools/build_boss_revival_check.bat
```

本次构建与离线回归结果记在交付说明。没有注入游戏或逐个复活实测。原始资源仍有 13 个找不到定义的 `InitializeEvent` 调用，以及未找到的 `common_macro.emevd` 链接；207 个主击败写入都已找到，缺口保留在证据中，不能据此宣称所有游戏内场地行为已完全验证。
