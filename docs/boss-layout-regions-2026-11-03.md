# Boss 名称对齐、地区与自动折叠

本轮以 `f721010` 为 Rust 基线，代码提交为 `6a19db4d86163ae2bd81c71197f55c64a1340bdc`，对照固定 C++ 提交 `afab7e14db2b62ae0bede980d5d0c96634321350`。修正列表布局、地区粒度及切区折叠；此前闪烁和菜单预加载的游戏内验收仍待用户确认。

## 名称对齐

此前 `[+]`、`[ ]`、`[?]` 按各自文字宽度分配按钮，比例字体下名称起点不同。现在用当前按钮字体测量三个状态的最大宽度，加按钮内边距，统一分配状态列。名称仍用 egui 的剩余宽度布局、截断和悬停全文，不靠补空格。已完成名称保留弱化颜色；只有有效存档、已完成且有外部配方的行可打开复活确认。

## 地区与当前玩家区域

旧 C++ 的完整目录为 32 个大区：基础游戏 23 区、DLC 9 区。此前 Rust 按 `BonfireWarpSubCategoryParam` 划分，真实归档有 95 组，并将 tab 与子区文字拼接成标题。本轮恢复旧版大区粒度；地区标题读取当前语言 `PlaceName`，不打包地区翻译表。啜泣半岛在旧 C++ 中本就是独立大区，继续保留；漂流墓地、风暴山丘等赐福子区合入对应大区。

地区级关系保存 32 个稳定文本 ID、旧版 123 个玩家地区前缀、整图／赐福子区关系，以及三个局部地点关系。不包含 Boss 名称、完成旗标或 207 项分类白名单。PlayRegionParam 的 `bossAreaId` 和 16 个 `bossId` 只辅助已由生命条事件发现的战斗归类；冲突关系不当作唯一归属。

三个地点关系均使用当前 WorldMapPoint 的坐标，在同图或同一地表世界的相邻 tile 内，按 64 游戏单位的三维半径关联：

| `6100900` | 无主猎犬的封印监牢 | 宁姆格福 | GameArea 与地图标记隔一个 tile，按 256 单位归一后约 20.77 单位 |

完成归类仍不足时，使用当前赐福和明确地区关系的位置锚点兜底，只在同一 `m60` 或 `m61` 世界、每轴相距不超过 2 个 tile、三维距离不超过 512 单位内查询。地下和两个地表世界不混用；未知位置仅取地图块中心并省略未知高度。这是近邻参考，不能表示精确边界。真实归档有 11 项使用该兜底，均有有效 Param 位置，距离为 73.79–246.70 单位；每项来源见 [近邻证据](evidence/boss-layout-2026-11-03/neighbourhood-fallbacks.json)。没有可用依据时保留地图／子类分组，不强凑 32 组。

最终真实归档为 **207 场、32 个大区、0 个未知完成条件**。旧 207 场主完成旗标、完成集合和具名成员均保留。206 项地区归属与旧版一致；玛丽戈按 PlayRegionParam 行 `6830000`／`6830001` 归入青蓝海岸，旧 C++ 将其列在卡罗隐藏墓地且地点为空。该项保留 Param 归属。完整逐项表见 [207 项地区对照 CSV](evidence/boss-layout-2026-11-03/old-to-new-regions.csv) 和 [32 大区数量](evidence/boss-layout-2026-11-03/groups.json)。

顺便修正两条确定的错误地图表示：黄金河马和梅瑟莫的 GameArea 复制了地图族 `15`，实际生命条事件均在地图族 `21`，因此改用 `m21_00_00`／`m21_01_00`。同地图族中的合法相邻 tile 位置继续保留。跨场代表事件优先选择主完成成员，再按稳定键排序；异步文件完成顺序不再使阿杜拉或兰斯桑克斯的代表位置跳到早场。未改变战斗归并或复活写入。

目录和玩家定位使用同一个稳定大区键。C++ 的 `mapId` 实际是 `FieldArea.current_play_region_id`，并按 `/1000` 查地区；它并非 Minimap 使用的 packed 地图块编号。因此不再用「同地图块内第一条 Boss」推测玩家地区。开放世界同一地图块可能跨区，DLC 还有垂直层次，不能以相邻地图编号代替该字段。

新的可选 Host V1 尾部服务 `read_boss_region(user, context, out)` 只在 update 侧读取。它复用已有 FieldArea 动态扫描结果，并检查 RTTI、读取布局和当前存档上下文；读取失败为未知，不改变最后有效地区。原 32 字节 `BossState` 和 224 字节 Boss 状态前缀保持不变。新尾部以 `CAP_BOSS_REGION` 和 232 字节表长检查；旧短表不读取尾部，自动切区降级为保留手动状态。Minimap 继续只消费原 176 字节前缀。

本包核心另开放第七张目录参数表 PlayRegionParam（组号 38、数据版本 9）。缺少该表时明确显示「正在等待游戏地区参数」，不创建文件任务或反复更换目录代次。升级本包时应同时更新核心和 Boss，不能仅将新 Boss 放进不提供该表的旧核心。

## 展开状态

- 第一次目录及玩家地区都有效时，只展开当前大区，其余收起。目录先到或玩家地区先到都能初始化。
- 有效大区改变时，执行一次相同重置。同区普通帧、同区内地图块／变体变化不覆盖手动展开和收起。
- 存档、加载中地区或读取状态暂时未知时，保留最后有效地区和折叠选择。恢复到同一区不触发重置。
- 搜索、只看未完成或地区下拉筛选期间，更新当前区标记，但延后自动重置。若期间切区，清除全部筛选后只应用最新有效地区一次；同区切换筛选不重置手动选择。
- 搜索继续尊重手动折叠：匹配组会显示标题，点击可展开。组计数仍为全组进度。C++ 没有这些筛选控件，这部分是 egui 界面的交互规则。
- 重新读取资源或真正 Param 地址换代后，新目录重新初始化一次。进度更新和条件地点文字变化不会重置折叠。紧凑模式不构造完整列表，展开时使用最新状态。

旧 C++ `renderFull` 仅在 `regionIndex` 变化时对所有节点执行 `SetNextItemOpen(i == autoExpandRegion)`；同区手动操作保留。旧版也不自动滚动到该区。本轮按这一行为恢复地区折叠，并为当前新增筛选保留可操作状态。完整 C++ 行为及 32 区清单见 [固定源码审计](evidence/boss-layout-2026-11-03/cpp-audit.md)。

## 升级与最小复测

退出游戏后替换包内三个 DLL。七份模板／关系配置内容与原包一致，已有配置、`configs/boss-ui.json` 和 `Challenge.txt` 均保留。默认 `=` 打开完整列表；确认完成与未完成名称对齐，跨大区后仅当前区展开，同区手动展开其他区后等待更新仍保留。搜索期间切区应保留结果折叠，清除全部筛选后再仅展开新当前区。

离线归档、真实 DLL 和 WARP 检查不代表已经在用户游戏进程中复验。闪烁及菜单预加载仍待现场确认；没有启动、注入、安装或替换用户运行中的游戏文件。
